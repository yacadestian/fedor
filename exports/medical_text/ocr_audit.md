# Проверка OCR (2026-09-02)

Сверка RouterAI `qwen/qwen3.7-flash` с оригиналами на Яндекс.Диске
(`/Анализы.` — 184 файла, `/healthbot/mail_medical` — 4 PDF + 2 sidecar).
Локальный OCR не использовался.

## Короткий ответ

**Цифровые PDF — нормально.** Текстовый слой читаемый, цифры совпадают с бланком.

**Чёткие фото бланков (~70–100 КБ, WhatsApp) — нормально.** Ключевые значения ОАК/биохимии/коагуляции совпали с оригиналом.

**Мелкие/повёрнутые фото (~20–30 КБ) — плохо.** Модель путает ФИО, дату рождения, часть цифр и подписи строк.

**CID-PDF без vision — провал.** Sidecar консультации 2018 был `(cid:…)`-кашей. Vision API читает бланк верно (группа крови 0(I), Rh+), но код отбрасывал OCR, потому что каша *длиннее* нормального текста. Это исправлено.

Ложные «гемоглобин 334» / «тромбоциты 9.9» в `ocr_review.md` — **не ошибка OCR**. На бланке это MCHC и MPV; экстрактор склеивал индексы ОАК с Hb/PLT.

## Что изменено в коде после проверки

1. `pdf_to_text`: при CID-слое брать vision OCR, даже если он короче каши.
2. Алиасы MCH/MCHC/MCV/MPV/RDW/PDW — больше не мапятся на Hb/эритроциты/тромбоциты.
3. Обрезка префикса `</think>`, который flash-модель иногда клеит к тексту.
4. В промпт экстрактора — явное правило про индексы ОАК.

На Диск залиты исправленные sidecar: vision-текст 2018 (группа крови) и `.txt` из слоя PDF для двух бланков 2019.

CSV/`ocr_review.md` **не пересобирались** (нет `data/history_bundle`). Ложные Hb 334 в старом экспорте останутся, пока не будет повторного `build_medical_results.py`.
